# 🎣 Sanctuary Hooks System

## Overview

The Sanctuary uses a **two-tier hooks architecture**:

1. **Generated Hooks** (`src/hooks/generated/`) — Auto-generated by GAIA from the database schema. One file per table, five hooks per file. **Always use these for data access.**

2. **Manual Hooks** (`src/hooks/`) — Hand-crafted hooks for auth, permissions, UI state, and cross-cutting concerns. These **compose generated hooks** rather than calling the database directly.

## 🏗️ Generated Hooks Pattern

Every generated hook file follows an identical 5-hook pattern:

### Standard Exports

```typescript
// Fetch single record by ID
export function use{Table}(id: string | undefined)

// Fetch paginated list with filters
export function use{Table}List(params?: {
  page?: number;
  limit?: number;
  filters?: Record<string, string>;
  sort?: string;
  order?: 'asc' | 'desc';
})

// Create mutation
export function useCreate{Table}()

// Update mutation
export function useUpdate{Table}()

// Delete mutation
export function useDelete{Table}()
```

### Key Characteristics

- **API-First**: All hooks call `/api/generated/{deity}/{table}` endpoints
- **Type-Safe**: Imports `{Table}Row`, `{Table}Insert`, `{Table}Update` from generated types
- **Consistent Error Handling**: Returns `{ data, loading, error, refetch }` or `{ create/update/delete, loading, error }`
- **No Direct Database Access**: Uses `fetch()` exclusively

### Usage Example

```typescript
import { useProfiles, useProfilesList, useUpdateProfiles } from '@/hooks/generated/hestia-core/profiles';

// Fetch a single profile
const { data: profile, loading, error } = useProfiles(userId);

// Fetch paginated list
const { data: profiles, total } = useProfilesList({ page: 1, limit: 20 });

// Update a profile
const { update } = useUpdateProfiles();
await update(profileId, { display_name: 'New Name' });
```

## 🔐 Auth & Permission Hooks

### `useAuth()`

**Source:** `useAuth.ts`  
**Data Access:** Calls `/api/generated/hestia-core/profiles/${userId}`  

```typescript
const { user, profile, loading, signIn, signUp, signOut, refreshProfile } = useAuth();
```

### `useRequireAuth(redirectTo?)`

**Source:** `useRequireAuth.ts`  
**Composes:** `useAuth`

Route guard that redirects unauthenticated users.

```typescript
const { user, loading } = useRequireAuth('/gateway');
```

### `usePermissions()`

**Source:** `usePermissions.ts`  
**Composes:** `useAuth`

Role and permission checks derived from the authenticated user's profile.

```typescript
const { isAdmin, isCreator, isVendor, isCommunity, can, loading } = usePermissions();
// can.viewAll, can.editAny, can.createProducts, can.moderate, etc.
```

### `useRequireRole(requiredRole, redirectTo?)`

**Source:** `useRequireRole.ts`  
**Composes:** `usePermissions`

Route guard for role-based access.

```typescript
useRequireRole('creator', '/apply');
```

## 👤 User & Profile Hooks

### `useUser()`

**Source:** `useUser.ts`  
**Data Access:** Calls `/api/generated/hestia-core/profiles/${userId}`

```typescript
const { user, profile, isLoading, isAuthenticated, isAdmin, userTier } = useUser();
```

### `useServerUser()`

**Source:** `useUser.server.ts`  
**Server-side only.** Uses server auth utilities.

```typescript
const { user, profile, isAuthenticated, isAdmin } = await useServerUser();
```

### `useProfile(targetUserId?)`

**Source:** `useProfile.ts`  
**Composes:** `useAuth`, `useProfiles`, `useUpdateProfiles`

Full profile management with preferences, badges, and role-specific profiles.

```typescript
const {
  profile, loading, permissions,
  updateProfile, updateNDPreferences, updateSensoryPreferences,
  awardBadge, hasBadge
} = useProfile();
```

### Specialized Profile Hooks

```typescript
// Current user's profile
const profile = useCurrentProfile();

// Profile by username
const { profile, loading } = useProfileByUsername('quantum_weaver');

// Creator-specific
const { creatorProfile, createCreatorProfile } = useCreatorProfile();

// Vendor-specific
const { vendorProfile, createVendorProfile } = useVendorProfile();

// Community-specific
const { communityProfile, hasJoinedHouse } = useCommunityProfile();

// Application submission
const { application, submitApplication } = useApplication('creator');
```

## 🎯 Best Practices

1. **Always use generated hooks for data access.** Never call `supabase.from()` directly in components or manual hooks.
2. **Compose, don't duplicate.** Manual hooks should wrap generated hooks, not reimplement them.
3. **Import types from generated files.** Use `ProfilesRow` from `@/types/generated/hestia-core/profiles`, not `Database['public']['Tables']`.
4. **Use the correct hook for the operation.** `useProfilesList` for lists, `useProfiles` for single records, `useCreateProfiles` for inserts.
5. **Handle loading and error states.** Every hook returns them—use them in your UI.

## 🔄 Regeneration

After database schema changes, regenerate hooks with:

```bash
npm run gaia
```

This updates all generated hooks in `src/hooks/generated/` to match the current schema.
