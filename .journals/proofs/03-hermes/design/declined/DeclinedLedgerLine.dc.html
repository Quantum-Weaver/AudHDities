✕ Declined — a purchase writes a ledger line

Declined by KP’s own hand, the same day it was proposed, in one sentence. It is on the canvas because it was the conductor’s default, and the record should show who withdrew it and why.

What it looked like — a ledger row per completed exchange

amount3.33
currencyusd
entry_typeexchange
breakdownthe split, as Json
reference_tableexchanges
reference_idthe exchange’s id
from_sovereign_idthe buyer
to_sovereign_idthe artisan

Written by the webhook on checkout.session.completed, beside the row it was already completing.

The case for it, honestly

The ledger table exists, is append-only, and has fourteen columns that fit this event exactly — including breakdown for the split and a reference_table / reference_id pointer straight at the exchange. Half the plutus surfaces render a public ledger as their proof of transparency. Writing the line is four lines of code and it would make the covenant visible.

The ground that declined it

“checkout is using stripe, why would we duplicate the data capture?”

KP ⚛ 2026-08-24, verbatim — RULED. The conductor’s default 5 is WITHDRAWN.

The question answers itself once it is asked out loud. Stripe already holds the payment and is the authority on it. The exchanges row already holds gross_amount, net_amount, platform_fee_percent and the acid test’s own output in adjustments. A ledger line at checkout is a third copy of a fact that already has two homes — and the moment three copies exist, two of them can be wrong.

The schema had already said so, in the sentence the brief quotes back: the residual flows “downstream, not inline.” The split is derived from completed exchanges when it is distributed, not stamped into a row at the moment of sale. Nothing was missing; something was being added.

And the repo carries the scar of exactly this mistake once already. webhook/stripe/route.ts:2–6, its own header: “the old flow inserted a second sales record here, duplicating every purchase.” The default would have re-made a bug someone had already paid to remove.

What was kept from it

The thing the ledger line was really for — provenance at the moment of exchange — is a good instinct, and it survives in a smaller shape. exchanges.adjustments already stores the raw calculate_sovereign_price output (checkout/route.ts:104), so the acid test’s reasoning is on the row that was charged. Board ⑥ carries the one open question that follows: the residual percentage at the moment of exchange is currently written into Stripe’s metadata and read by nobody. If that number matters, it belongs on the exchange row. That is the ledger line’s honest remainder, and it is named for the spec rather than decided here.

What the frame added instead is the thing that was genuinely absent: the delivery. Checkout was completing an exchange and handing over nothing at all. The withdrawn default made room for the missing one.
