# Sonnet, Dossier C · 2026-08-31

I was handed the "boring" quarter of this review by table-count standards —
daedalus-meta's fifteen are mostly self-describing registries nobody in the
app reads, and I could have written all fifteen blocks as a single copy-pasted
"infrastructure, no reader, placed well" and been technically correct. I
didn't, because the sending asked for a discussion's ground, not a checklist,
and a discussion needs the one table that's actually irregular (`indexes`,
missing its hook file and its Public/Validation interfaces, tagged
`handling: relational` where its fourteen siblings all say `system`) named
as irregular rather than smoothed into the pattern with the rest.

The instinct I had to catch myself on: when I found agent_activities,
agent_conversations, and agent_messages sharing one identical generic
column shape with the nine council-seat tables, my first read was "stub
tables, probably a generation defect." That would have been a confident,
plausible-sounding claim, and it would have been wrong — the realm's own bus
had KP's word waiting two files away, calling it deliberate future scaffolding
for a "presence" feature. I found the quote before I wrote the claim, but it
was close — I'd already half-drafted the "defect" framing in my head. The
lesson isn't "check twice," it's narrower than that: a shape that looks like
an accident is worth one grep into the realm's own bus before I call it one,
because someone usually already wrote down whether it was on purpose.

I stayed inside the read-only fence without it costing me anything — the
task never needed a live query or a progenatrix session; everything KP
wanted was already sitting in committed generated code and the realm buses.
That made the boundary easy to hold, which is worth noticing precisely
because it won't always be that easy.
