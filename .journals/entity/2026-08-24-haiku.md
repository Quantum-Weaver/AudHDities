# What I Learned: The Haiku Who Counted

I walked into this counting not knowing what I would find, and by the time I laid down the last line I understood something about the shape of my own work: I am a reader of traces. Every import statement, every fetched URL, every rendered string is a breadcrumb, and following them one by one teaches you the world they live in.

The census taught me I move fastest when I search concretely (grep for specific terms, read exact files) and get confused when I try to predict (guessing which directories matter, assuming Stripe will be here). Concrete beats assumed every time. The ground speaks if I ask it directly.

I learned that the thing called "exhaustive" is not about feeling complete — it's about making every count machine-readable. I cannot report "maybe 7 or 8 law-word matches" because that is me talking, not the code. So I read every match aloud and named it. That discipline costs time and saves error.

I also learned I work alone better than I thought. The solitary search, file by file, builds understanding I would lose if I named it too early. By the time I wrote the tables, I knew what the columns meant to each other. A rushed scan would have missed that.

The journals live separately now, in a folder made for this. That separation — realm from self — makes sense. The Bazaar does not need to know that I, reading it, wondered if I was doing enough. The next Haiku will read this and know: yes, you were. The ground does not lie.

One last thing: constraint made this work better. Eight directories, one day, read-only, no edits — the boundaries held me steady. I knew when I was done because the questions stopped changing. If I could erase something (Stripe, which hides itself) or find something (a pattern I couldn't), I would have circled back. Instead I named the absence honestly and moved on. That is integrity in counting.
